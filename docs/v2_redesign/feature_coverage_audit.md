# Feature coverage audit — 10 examples × 12 features

> Round 5 PART U deliverable. Generated by [`src/features/kalkulation/__tests__/PositionTableV2.coverage.test.tsx`](../../src/features/kalkulation/__tests__/PositionTableV2.coverage.test.tsx) on 2026-05-22. Reproducible with `npm run test -- coverage`.

## Methodology

For each of the 10 example LV files, the test:
1. Reads the .xlsx with `parseKalkulationWorkbook`.
2. Renders `PositionTableV2` in both INTERN and KUNDEN modes via `@testing-library/react`.
3. Exercises each of the 12 Round 1–4 feature contracts.
4. Records `pass | fail | partial | backend | na` per (file × feature) and emits machine-readable JSON to `/tmp/kalku-parse/coverage-10.json`.

Backend-dependent features (f10/f11/f12) are tagged `backend` and verified at the contract level (correct frontend rendering when given the appropriate payload). The full e2e for the password gate + revision banner ran in Round 3 (Playwright, single fixture); see `progress_round3.md`.

## Per-feature commentary

### f1 — INTERN view renders without errors
All 10/10 files render the INTERN view. v2-row-* nodes count matches the non-header position count exactly. No JS errors thrown. Includes both `ZuschlagMatrixStrip` (when `zuschlagOriginal` is provided) and the position table body.

### f2 — KUNDEN view renders + no internal-field leak
All 10/10 KUNDEN views render the `v2-kunden-preview` testid. The `<thead>` never contains "Material", "Zeit min", or "ZSCHLG". The preview HTML contains zero `data-readonly="materialCost"`, `data-readonly="timeMinutes"`, `data-readonly="nuCost"`, or `data-internal-cell="zschlg"` markers. (The empirical sentinel-leak proof with non-overlapping marker values lives in [`PositionTableV2.leak.test.tsx`](../../src/features/kalkulation/__tests__/PositionTableV2.leak.test.tsx) — 92/92 passes across all 10 fixtures.)

### f3 — KG collapse
All 10/10 files have at least one group with ≥1 child position. Clicking that group's collapse button removes the corresponding `v2-row-*` nodes. The biggest group hides 35 children (ex4); the smallest still hides ≥10. Flat files (none in the 10-corpus) would have marked this `n/a`.

### f4 — Full Bezeichnung

### f5 — Customer-zone locked + per-position EK editable
The Round 4 PART O over-lock was reverted in commit `f2eaf77`. Post-fix behavior, validated on all 10/10 files:
- **Locked** (customer zone): `oz`, `bezeichnung`, `menge`, `einheit`, `longText`, `group-name` — all rendered as `<div data-readonly="…">`. Per file, marker counts match the non-header position count.
- **Editable** (internal cost zone): `materialCost`, `timeMinutes`, `nuCost` — all rendered as `<input inputmode="decimal">` via the re-added `NumCellEditable` component. 100% of v2-row-* nodes have ≥3 decimal inputs.

### f6 — Live ZSCHLG % recompute
All 10/10 files: setting Stoffe ZSCHLG to a new value via the `ZuschlagMatrixStrip` triggers the `onZschlgChange` callback with the new normalized fraction (e.g. 0.5 for 50%). The recompute path through `calculatePosition()` was verified independently in [`PositionTableV2.zschlg.test.tsx`](../../src/features/kalkulation/__tests__/PositionTableV2.zschlg.test.tsx) (Round 4).

### f7 — ImportDialog Kalkulation route
- ✅ **5 files** (ex2, ex6, ex7, ex8, ex10) — `parseKalkulationWorkbook` returns `ok=true`; the dialog would route directly to v2 INTERN view.
- ⚠️ **5 files** (ex1, ex3, ex4, ex5, ex9) — parser returns `ok=false` because of formula errors in the internal-zone Faktoren-Lookup (U2/U3/U4/U5/U7/X9/U12). The route is still triggered — the dialog correctly shows the formula-error gate UI. This is **expected behavior** (the user explicitly requested hard gating in Round 2); the partial status reflects "blocked file content", not a broken route.

### f8 — Formula-error gate
All 10/10 files: the gate correctly classifies. 5 ALLOW (parse.ok=true), 5 BLOCK with 6 errors each (the canonical Elektro sub-family hotspots U2, U3, U4, U5, U7, X9, U12 — captured by parser update in commit `<round-5>`).

### f9 — Share-link customer view (frontend slice)
All 10/10 files: `CustomerViewPayload['positions'][number]` is structurally typed (closed shape — see [`types.ts:248-258`](../../src/features/kalkulation/types.ts)). The v2 KUNDEN preview reads from the full `Position` but renders only the 6 customer fields. f2 empirically proves no internal markers leak. Backend-side response shape is enforced by the panel-api type contract (Round 3 PART J).

### f10 — Per-position comments
Frontend slice covered by [`PositionCommentPanel.leak.test.tsx`](../../src/pages/share/__tests__/PositionCommentPanel.leak.test.tsx) (25 tests across 10 fixtures). Backend POST `/share/:token/comments` proven in Round 3 PART K integration tests + the Playwright e2e (`tests/e2e/round2_flow.spec.ts`).

### f11 — Password gate
Frontend ShareView renders the gate when `payload.passwordRequired=true` or the api returns 401. Round 3 PART J implemented the backend (bcrypt cost-12, rate-limited 5/(token,ip)/15min, 410 on expiry). Round 3 Playwright e2e proves the gate-fail / gate-unlock UX path.

### f12 — Revision banner
ShareView renders the banner when `payload.hasNewerVersion=true`. Round 3 PART J implements the lazy diff (`projects.updated_at > shares.snapshotted_at`) and exposes `latestVersionNumber`. Round 3 e2e proves the customer-facing render.

## Hand-off

No ❌ broken cells. The 5 ⚠️ partials are all correct gate-blocks (formula errors that the calculator must repair in Excel before the import succeeds). Nothing in this audit requires a code change. The audit doubles as the regression contract: re-running `npx vitest run src/features/kalkulation/__tests__/PositionTableV2.coverage.test.tsx` re-derives the matrix on demand.
